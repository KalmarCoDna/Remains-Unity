# TD-09: journey diagnostics lifecycle

JourneyTransportTrace previously subscribed to NetworkDiagnostics in the probe initializer, before Mirror's AfterSceneLoad ResetStatics. That reset erased the subscription and could produce zero message counts despite live traffic. The trace now subscribes through CoopSession.ClientReady/ServerReady, including reconnect. Binding removes only this instance's callback before adding it, so host startup's two readiness events do not double the counters. Destruction removes both session and diagnostic callbacks. Transport packet callbacks remain read-only and are removed at destruction.

Native Unity 6000.0.39f1 check: Remains.Editor.JourneyTransportTraceChecks.RunBatch, exit 0. The fixture resets Mirror statics, starts a real in-process Mirror local host connection, sends a serialized ReadyMessage and server NotReadyMessage reply through its actual queues/handlers, then disconnects and reconnects. Each cycle has exactly two outgoing and two incoming diagnostic messages after repeated readiness events. Destruction leaves no static callbacks. This is actual local Mirror message delivery, not two-PC LAN/UDP coverage. With the original trace implementation, the same real messages arrived but the diagnostic counter assertion failed, exit 1.

Evidence: /workspace/scratch/td09-trace-native-3.log (fixed), td09-trace-baseline.log (original failure). The first two fixture iterations exposed missing Edit Mode transport initialization and incomplete host registration; those fixture issues were corrected before comparison. No gameplay or protocol changes.
